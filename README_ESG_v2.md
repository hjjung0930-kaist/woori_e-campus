# 삼성SDI ESG 평가모델 2차 개선 (v2)

## 개선 내용

- 기존 `esg_rule_engine_improved.py`의 검색어 확장, 검색 후보 다양화, 자동 2차 검색을 유지합니다.
- **BM25 어휘기반 검색 점수**를 기존 키워드 점수에 추가해 긴 문서에서 특정 단어 반복만으로 검색 순위가 높아지는 현상을 완화합니다. 임베딩/벡터 검색은 포함되지 않습니다.
- **인용 원문 검증**: 공백·줄바꿈·일부 PDF 문자형식 차이를 정규화해 인용문을 대조합니다. 그 외 텍스트가 변형된 경우에는 매우 높은 유사도(0.96 이상)가 필요합니다. 문서명 및 페이지도 일치해야 합니다.
- **0점 보수적 처리**: 단순히 자료가 없다는 이유로 0점을 부여하지 않습니다. 원문 인용에 명시적 부정·미충족 표현이 없으면 미확인으로 보류합니다. 명시적 부정 표현이 있어도 해당 규칙과 연도에 대한 판단은 사람 검토를 권장합니다.
- **결과 추적**: `인용일치도`, `검증상태`, `검색차수`, `후보근거` 열을 남깁니다.
- **GPT-5.1 사용시** temperature를 강제로 지정하지 않도록 변경했습니다. API와 모델별 지원 사항은 환경에 따라 다를 수 있습니다.

> 이 버전에서 1점은 원문 인용 존재만 기계적으로 검증하며, 인정조건을 모두 충족하는지는 LLM이 판정합니다. 정확성 보장이 아니므로 새로 판정된 항목은 사람이 확인해야 합니다. **스캔 PDF의 OCR, 표 전용 파서, 임베딩 검색은 아직 미구현**입니다.

## 설치

기존 프로젝트 폴더에 `esg_rule_engine_v2.py`를 넣고 설치:

```bash
/opt/anaconda3/envs/sumin/bin/python -m pip install pandas openpyxl pypdf openai
```

`.env` 파일은 Python 파일과 같은 폴더에 두고 `OPENAI_API_KEY=...`를 설정합니다. API 키는 공유하지 마세요.

## 권장 실행: 2차 개선 전 결과 중 미확인 항목만 재검증

```bash
/opt/anaconda3/envs/sumin/bin/python esg_rule_engine_v2.py \
  --rulebook "룰북.xlsx" \
  --pdf-dir "input_docs/삼성SDI" \
  --company "삼성SDI" \
  --target-year 2025 \
  --output "삼성SDI_4개보고서_평가결과_v2.xlsx" \
  --review-mode llm \
  --model "gpt-5.1" \
  --enhanced-search \
  --refine-unconfirmed "삼성SDI_4개보고서_평가결과_improved.xlsx"
```

**주의:** 이 명령은 기존 1/0/N/A 판정을 그대로 유지합니다. 기존 개선판의 0점 중 의심스러운 판정을 **다시 검증하려면** `--refine-unconfirmed` 옵션을 빼고 전체 111개를 실행하세요. v2와 기존 판정의 순수 비교도 전체 재실행이 더 적합합니다.

## 결과 파일 확인 순서

1. `점수요약`: 판정완료/미확인 및 근거확인률을 확인합니다. 미확인 감소 자체가 정답률 상승이라는 뜻은 아닙니다.
2. `판정결과`: `인용일치도`, `검증상태`, `최종인용문`, `최종문서`, `최종페이지`를 확인합니다.
3. `검토대상`: `0점명시근거부족`, `인용검증실패` 등 사유를 점검합니다.
4. 전/후 동일 조건으로 실행했다면 수동 정답셋을 사용해 1점/0점 판정의 정밀도를 비교하세요.

## 남아 있는 한계

- 텍스트 기반 BM25는 의미상 유사하지만 단어가 겹치지 않는 문장 검색에 한계가 있습니다.
- PDF 표, 텍스트가 없는 스캔 페이지는 정보가 유실될 수 있습니다.
- `0건`, `없음` 등의 명시적 표현이 있더라도 그것이 해당 규칙의 미충족을 뜻하는지는 별도 확인이 필요합니다.
- 문서 전체의 정확한 성과연도 감지에 한계가 있습니다. 기준연도가 섞인 자료는 수동 교차검증하세요.
- 실제 삼성SDI PDF 4개와 API 호출을 통한 v2 성능 평가는 이 환경에서 수행하지 않았습니다.
